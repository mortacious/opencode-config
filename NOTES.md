# NOTES - fusion-tools implementation

## Goal
Implement and harden the local OpenCode v2 plugin package plugin-src/fusion-tools: (1) advisor - oh-my-pi style peer reviewer watching build/plan sessions with hot-reload-safe activation gating; (2) fanout - parallel worktree worker fan-out with schema-validated results; (3) steer - a /steer command that forwards a message to the most recent still-running subagent. This round (user decisions given up front): DISABLE the advisor via config (code + config keys retained for later re-enable), DROP the pending advisor cost-gating fix (recorded as a known issue), finish the fanout sandbox/recursion fixes, make every subagent-type agent explicitly unable to spawn subagents (delegation runs only through build/plan), and add the small /steer module. Do NOT commit; cli.json and the "Amenable Thor 1" provider block untouched.

## Decisions
- Advisor disabled purely by config: opencode.jsonc plugins entry "advisor": {"enabled": false, ...} - every other advisor key (model, scope, activation, minStepsTurn, minTurnDeltaChars, failurePauseMs) and all comments kept. Re-enable = set enabled true (after fixing the known issue below). The agent definition agents/advisor.md stays registered (agent defs are independent of the plugin gate).
- Known issue (blocks re-enable): the idle-complex turnDeltaChars gating measures the CUMULATIVE request payload of the turn (JSON.stringify of all messages accumulated over context-hook calls), not a per-turn delta of NEW content. A long session crosses the 8000-char threshold every turn regardless of what the turn actually added, so idle reviews fire too often. Must be fixed to a true per-turn delta before re-enabling the advisor.
- Advisor module registers NOTHING when disabled (advise tool, context hook, /advisor command all gated on cfg.enabled; the rehydrate block too). fanout has its own options.fanout.enabled gate and stays registered when the advisor is off; the context hook registers whenever advisor OR fanout is active (it also shapes fanout session tools). steer registers ALWAYS (independent of both).
- v2 permission resolution fact (verified against tag v2.0.18 source, packages/core/src/permission.ts): rules resolve with findLast - the LAST matching rule wins. Therefore the worker session's catch-all deny sits FIRST as the fallback that later specific rules override; a catch-all deny placed last would deny everything below it and brick the worker. The spec's "catch-all deny last" wording was implemented as "catch-all deny first (lowest priority)" to satisfy the spec's real requirements: read/grep/glob/submit_result allows, edit+write allowed ONLY inside the worker's own worktree, explicit denies elsewhere, bash/shell/exec and subagent never re-allowed.
- v2 frontmatter quirk (verified: packages/core/src/config/plugin/agent.ts + issue anomalyco/opencode#50598): a markdown agent file whose frontmatter contains ANY non-native key (legacy `permission:` map, `mcps:`, `temperature:`, ...) routes the WHOLE frontmatter through the V1 decode path, which silently discards the v2 `permissions` array; the legacy `permission:` map is then the effective channel ("task" and "bash" are normalized to "subagent" and "shell" at load). Files using only native keys get the array applied.
- Delegation topology: subagent-type agents get BOTH a task deny and an explicit subagent-spawn deny; sidekick/reviewer/research/design lose their explore/research task allows (delegation runs only through build/plan, per user decision). build/plan keep their task allowlists. Built-in agents general/compaction/title/summary cannot be edited from this repo - noted, untouched.
- steer child tracking is in-memory per plugin generation (best effort): a child counts as running unless the plugin saw session.idle for it; state resets on hot reload. Confirmed acceptable - steering is inherently live-session work.
- The render self-filter set now includes "steer" (lib/render.js SELF_METADATA_VALUES = advisor, advisor-note, steer) so /steer feedback asides never echo into advisor transcript reviews.
